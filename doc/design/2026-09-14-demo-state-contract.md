# 公共 Demo 状态契约

状态：待确认

## 1. 问题

领导演示由七幕组成，但七幕不是七个独立功能。后一幕必须能够消费前一幕已经形成的目标、约束、客户、策略、校验和反馈结果；页面跳转、重复播放和模型波动又不能改变关键演示结论。

因此需要一个公共状态契约，统一表达一次演示从创建到结束期间的业务事实、决策证据、执行记录和展示进度。

## 2. 目标与非目标

### 目标

- 让七幕共享同一个演示上下文，并明确每幕的输入、产物和完成条件。
- 确保关键数值、名单、规则结论和状态流转稳定、可复现。
- 保存每个业务结论的依据、规则版本、模型参与方式和时间信息。
- 允许演示暂停、继续、向前查看和重新开始，而不污染业务状态。
- 保持契约能够从合成数据和模拟渠道平滑替换为真实数据与外部接口。
- 在大模型不可用时，仍能完成确定性业务链路的演示。

### 非目标

- 不在本契约中确定数据库、中间件、前端框架或部署方式。
- 不定义生产级客户主数据、保单、产品和渠道的完整领域模型。
- 不把领导演示中的固定人数、客户编号或评分写成通用业务规则。
- 不让大模型输出直接成为授权、频控、适当性或人员资格的最终判断。
- 不在当前设计中解决多活动并发、海量实时事件和生产级灾备。

## 3. 核心边界

一次公共 Demo 状态以“演示运行”为聚合边界。一次运行代表从经营人员下达目标，到策略建议完成审批或演示终止的一次完整故事实例。

公共状态分为四个相互隔离的部分：

1. **业务事实状态**：目标、边界、数据快照、机会、客户、旅程、校验、执行、反馈和策略版本。它决定演示业务结果。
2. **决策与审计状态**：规则命中、评分贡献、证据引用、模型及规则版本、人工审批和 Agent 运行记录。它回答“为什么”。
3. **演示控制状态**：当前幕、已解锁幕、展开项、播放模式和演示提示。它只影响展示，不得改变业务结论。
4. **运行健康状态**：模型、规则、数据和渠道模拟器是否可用，以及是否正在使用降级结果。它回答“当前结果是怎样产生的”。

其中，业务事实和审计信息属于可回放事实；演示控制属于临时视图状态，不能作为业务判断输入。

## 4. 演示运行的公共头信息

每次演示运行至少需要表达以下语义：

| 信息 | 含义 |
|---|---|
| 运行标识 | 唯一标识一次完整演示，所有幕间产物和事件均引用它 |
| 场景标识与版本 | 指明使用哪套合成数据、故事角色和预置事件 |
| 随机种子 | 保证需要抽样或排序的确定性逻辑可复现 |
| 运行修订号 | 标识业务状态版本，防止重复点击或并发请求覆盖新状态 |
| 生命周期状态 | 区分已创建、进行中、待审批、已完成、失败或已终止 |
| 创建与更新时间 | 支持审计、排序和演示恢复 |
| 数据基准时间 | 所有“近期”“近 30 天”“七天后”等相对时间的统一计算基准 |
| 数据模式 | 明确当前使用合成、脱敏或真实数据；领导版默认为合成数据 |
| 执行模式 | 区分预设引导、自由探索和回放；首版只需保证预设引导 |

场景标识、版本、随机种子和数据基准时间一经开始运行不得改变。需要切换场景时，应创建新的演示运行。

## 5. 七幕共享的业务状态

### 5.1 经营任务与边界

保存经营人员的原始目标，以及由 Agent 整理后的结构化任务摘要。结构化内容至少覆盖：

- 分析对象与时间范围；
- 希望改善的经营结果；
- 数据用途和授权边界；
- 营销许可和渠道许可要求；
- 触达频控；
- 敏感状态排除要求；
- 产品适当性要求；
- 承接人员资格要求；
- Agent 可执行的动作与必须转人工的动作；
- 停止条件；
- 尚未确认的假设。

硬边界必须带有来源和版本，并由确定性规则执行。Agent 可以补充解释或提示缺项，但不能放宽硬边界。

### 5.2 数据快照与来源

一次运行引用一份不可变的数据快照。快照应说明：

- 客户、保单、行为、授权、敏感状态、渠道、人员和历史结果的来源；
- 每类数据的更新时间与有效范围；
- 是否为合成或脱敏数据；
- 数据口径版本；
- 已知缺失或质量提示。

业务产物引用快照中的证据，不复制或暴露不必要的敏感字段。

### 5.3 机会组合

第二幕形成机会组合，而不只是保存一个最终推荐。每个候选机会应包含：

- 机会定义和适用人群口径；
- 客群规模、需求强度、预计响应、触达成本和风险指标；
- 数据来源、基准时间和识别置信度；
- 支持与限制该机会的主要证据；
- 是否被推荐，以及推荐或未推荐原因。

进入圈客前必须明确选中的机会。默认可采用 Agent 推荐，但需要保留“由谁选择”的记录。

### 5.4 客群筛选结果

第三幕的客群状态由三个层次组成：

- 机会客户：符合机会基本定义的人群；
- 可经营客户：通过授权、敏感状态、频控和初步适当性等约束；
- 优先客户：在可经营客户中，根据需求、意向、承接价值和风险进行排序。

每位客户都应保存：

- 当前所处层次和优先级；
- 入选信号及其发生时间、有效期和证据引用；
- 排除或降级原因；
- 分数及可解释贡献项；
- 最近一次确定性校验结果；
- 当前可采取与禁止采取的动作。

漏斗汇总必须由客户明细推导，不能单独维护一套可能与名单不一致的数字。

### 5.5 客户旅程与策略包

第四幕产出的不是自由文本，而是可被校验和执行的策略包。策略包应表达：

- 适用机会、客群和策略版本；
- 初始动作；
- 渠道、内容意图、建议时间和承接角色；
- 等待条件和最长等待时间；
- 对打开、测算、浏览、咨询、拒绝、退订和无响应等事件的分支；
- 转人工、暂缓和退出条件；
- 每个选择的业务理由；
- 生成依据和待确认事项。

内容可以由大模型生成，但旅程结构、允许的动作和停止条件必须能够被普通代码检查。

### 5.6 校验、分发与人工任务

第五幕需要同时保存逐项校验结果和最终处置结果。校验至少覆盖：

- 数据与用途授权；
- 渠道许可；
- 触达频控；
- 投诉、理赔等敏感状态；
- 产品与客户适当性；
- 内容合规；
- 人员资格与服务范围；
- 可服务时间和渠道可用性。

最终处置限定为通过、拦截、暂缓或转人工确认。每项校验记录规则版本、输入证据、结果和原因。分发任务必须引用已经通过的校验快照；后续客户状态变化时，不得沿用已失效的校验结果。

### 5.7 客户动态状态与事件时间线

第六幕以客户事件驱动状态变化。事件需要包含事件标识、客户、类型、发生时间、接收时间、来源和业务载荷摘要。

系统处理事件后形成：

- 事件是否被接受、忽略或判为重复；
- 客户意向分变化及贡献项；
- 信号有效期；
- 旅程节点变化；
- 下一建议动作；
- 是否创建、更新或取消专业人员任务。

拒绝、退订和投诉等负向信号优先级高于浏览、打开和测算等正向信号。一旦命中停止规则，历史高分不能继续触发营销动作。

### 5.8 经营评估与策略迭代

第七幕保存经营结果、实验比较和策略变更建议：

- 有效响应、测算完成、专业人员接续、有效线索、成本和负反馈指标；
- 实验组、对照组、样本范围、观察窗口和结论限制；
- 渠道、时段和旅程分支的表现；
- 合规拦截数量与原因；
- Agent 给出的优化建议及证据；
- 人工审批决定、意见和时间；
- 候选策略版本、已发布版本和可回滚版本。

Agent 只能创建候选建议。没有人工批准，不得将候选策略标记为已发布。

## 6. 决策证据契约

机会推荐、客户入选、旅程选择、校验处置、分数变化和策略建议都应关联一个决策记录。决策记录至少回答：

- 做出了什么决定；
- 决定作用于哪个机会、客户、旅程或策略；
- 使用了哪些事实和证据；
- 哪些规则或评分项参与；
- 哪部分来自确定性计算，哪部分来自模型解释；
- 使用的规则、数据、提示词和模型版本；
- 决定发生的时间和执行主体；
- 是否需要人工确认，以及确认结果。

模型生成文本不能成为硬规则已经通过的唯一证据。页面展示的解释必须能追溯到实际决策记录，不能另行生成一套与真实处理不一致的理由。

## 7. 演示控制状态

演示控制只描述“现在展示什么”，建议包含：

- 当前幕；
- 已完成、可进入和锁定的幕；
- 当前聚焦的机会、客户、旅程节点或策略版本；
- 当前展开的证据面板；
- 是否开启自动讲解；
- 当前演示提示和推荐的下一操作。

切换当前幕、展开客户或返回上一幕不得修改业务事实。只有明确的业务动作，例如选择机会、确认任务、注入事件或审批策略，才产生新的业务状态修订。

## 8. 每幕完成条件与交接产物

| 幕 | 完成条件 | 提供给下一幕的产物 |
|---|---|---|
| 第一幕 | 目标已结构化，硬边界完整且来源明确 | 经营任务、边界清单、数据范围 |
| 第二幕 | 至少形成多个可比较机会，并选定一个重点机会 | 机会组合、选中机会、推荐证据 |
| 第三幕 | 漏斗与客户明细一致，每位客户有入选或排除理由 | 分层客群、优先客户、客户证据 |
| 第四幕 | 重点客户存在结构化旅程，包含继续、暂缓、转人工和退出分支 | 策略包、旅程版本、生成依据 |
| 第五幕 | 重点任务完成逐项校验，并形成明确处置 | 校验报告、模拟执行任务、人工任务 |
| 第六幕 | 注入事件已被处理，客户状态和下一动作完成更新 | 事件时间线、最新客户状态、跟进任务 |
| 第七幕 | 形成实验结论和候选策略，审批结果被记录 | 评估报告、审批记录、策略版本 |

某幕缺少完成条件时，下一幕保持锁定；演示人员可以返回查看，但不能用页面操作伪造完成状态。

## 9. 状态变化与回放原则

业务状态采用“当前快照 + 不可变事件记录”的语义：

- 当前快照用于页面快速渲染；
- 事件记录保存导致状态变化的业务动作和结果；
- 相同场景、版本、随机种子和动作序列应得到相同确定性结果；
- 重复注入同一个事件不得重复加分或创建重复任务；
- 业务动作基于旧修订号时不得静默覆盖新状态；
- 回放只重建状态，不重新请求大模型产生新的关键结论；
- 大模型输出需要保存为当次运行产物，回放时复用原结果。

“重新开始演示”应创建一条新的运行，而不是清空或改写原运行。原运行可保留用于审计，也可按演示数据保留策略统一清理。

## 10. 降级与错误状态

运行健康状态分别记录数据、规则、模型、渠道模拟器和事件处理能力。降级原则如下：

- 大模型不可用：继续使用确定性产物和预置解释，清晰标注降级，不阻断主故事。
- 规则不可用：不得伪造通过，相关幕进入阻塞或使用明确标记的场景预计算结果。
- 渠道模拟器不可用：可以展示已校验任务，但不能声称已经发送或收到回执。
- 数据不完整：在相关指标和决定上显示数据质量提示，不允许模型补造缺失事实。
- 单个客户处理失败：记录失败原因，不影响其他客户结果；漏斗需区分失败与业务排除。

失败状态必须保留已经形成的事实和 Trace，支持从安全节点重新尝试，不能用一次全局异常抹掉全部上下文。

## 11. 关键不变量

1. 所有业务产物属于且仅属于一次演示运行。
2. 运行开始后，场景版本、随机种子、数据基准时间和数据快照不可变。
3. 漏斗汇总由客户明细推导。
4. 未通过硬校验的任务不能进入已分发状态。
5. 页面展示状态不能修改业务事实。
6. 负向停止信号优先于正向意向信号。
7. 同一客户事件只处理一次。
8. 模型不能修改硬规则、审批结果或已发生事件。
9. 未审批的策略建议不能成为已发布策略。
10. 每个关键结论必须能够追溯到证据与版本。
11. 合成数据不得被展示或导出为真实客户数据。
12. 重放不能改变已经保存的关键故事结论。

## 12. 场景数据与公共契约的关系

公共契约只定义语义，不固定具体故事数字。下列内容属于领导演示场景包：

- 三个候选机会的名称和指标；
- 86、41、12 的漏斗结果；
- C001、C028 等故事角色；
- 68 到 86 的评分变化；
- 口袋 E、绿 E 通等渠道名称；
- 预置的打开、测算、浏览、拒绝和审批事件。

场景包可以替换，公共状态契约不随具体故事数字变化。场景包本身需要版本化，并在加载时验证数据自洽性。

### 12.1 前三幕 Mock 原则

状态：已确认（2026-09-15）

前三幕采用“合成原始数据 + 确定性计算得到固定故事结果”的 Mock 原则：

- Mock 的对象是尚未接入的外部数据源、规则配置和历史基准，不是正常链路中的最终业务结论。
- 第一幕的结构化经营任务、第二幕的机会指标与排序、第三幕的客户分层与漏斗，均从同一次运行引用的合成数据快照产生。
- 86、41、12 等漏斗数字必须由客户明细计算得到；机会规模、评分、排序和客户入选或排除结论同样不得与明细分开维护。
- 授权、频控、敏感状态、初步适当性等硬边界由确定性代码执行，大模型不能覆盖其结果。
- 大模型负责目标理解、结果解释和表达组织；模型不可用时可以复用已保存的结构化产物和预置解释，但必须标明降级来源。
- 相同场景版本、数据快照、随机种子和输入动作必须产生相同的关键故事结果。

## 13. 首版成功标准

- 能创建、继续和重新开始一次领导演示运行。
- 七幕使用同一运行标识，后一幕只消费已完成幕的正式产物。
- 预设场景重复运行时，关键人数、客户处置和评分变化一致。
- C001 的入选、通过、分数提升和转人工均能追溯到证据。
- C028 的暂缓由频控规则产生，不能被模型解释覆盖。
- 注入拒绝事件后，即使客户此前高分，也立即停止本轮营销动作。
- 策略建议只有经过人工审批后才能形成发布版本。
- 页面来回切换不会改变客户、任务或审批状态。
- 模型不可用时仍可完成确定性主链路，并显式显示降级状态。
- 从事件记录回放得到的业务状态与保存快照一致。

## 14. 待确认事项

1. 首版是否只支持一套预设场景，还是同时支持“领导演示”和“自由探索”两套模式。
2. 演示运行是否需要跨进程保存；若只用于单机演示，可先选择更轻量的持久方式。
3. 是否允许演示人员跳过某一幕；建议首版只能查看已完成幕，不能跳过业务完成条件。
4. 模型降级时使用预置解释还是 Fake 模型现场生成；建议关键讲解使用预置解释，非关键补充使用 Fake。
5. 人工审批在首版中是否需要登录身份；建议先保留审批主体语义，不提前引入完整身份体系。
6. 是否需要同时保留中文领导视图和技术 Trace 视图；建议共享状态，只提供不同展示层。
