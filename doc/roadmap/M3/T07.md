
可以，M3-T07 就应该收口，不再新增架构概念。

这一阶段唯一目标是：

> **把 M2 的动态 Plan、M3 的 Capability 执行、Continuation Policy 和 Replan 真正串成一个可运行闭环，并用少量 Behaviour Case 证明它成立。**

M2-Lite 原来只做到 `Goal → Plan`，明确没有实现 Capability 执行和 `CapabilityResult → Replan`；M3-T07 正好把这个缺口闭上。

---

# 一、M3-T07 最终链路

完成以后整个 BusinessAgent 应该变成：

```text
User Request
     │
     ▼
 Goal Parser
     │
     ▼
    Goal
     │
     ▼
   Planner
     │
     ▼
   Plan V1
     │
     ▼
ExecutionContext
     │
     ▼
┌──────────────────────────────┐
│       Execution Loop         │
│                              │
│ get_next_ready_step()        │
│          ↓                   │
│ execute_step()               │
│          ↓                   │
│ CapabilityResult             │
│          ↓                   │
│ decide_continuation()        │
│                              │
│ CONTINUE ─────────────┐      │
│                      │      │
│ REPLAN → Planner.replan()   │
│              ↓       │      │
│           Plan V2 ───┘      │
│                              │
│ FINISH / ASK_USER / STOP     │
└──────────────────────────────┘
```

这个时候才能真正说：

```text
Plan 会根据执行结果发生变化。
```

这正是 Roadmap 对 M3 的验收目标。

# 二、不要新增 `ExecutionEngine`

之前已经有：

```text
CapabilityExecutor
ExecutionContext
execute_step
get_next_ready_step
ContinuationAction
Planner.replan()
```

所以 T07 不需要再出现：

```text
ExecutionEngine
RuntimeEngine
ReplanEngine
BusinessWorkflow
WorkflowRuntime
AgentRuntimeV2
```

最合适的做法就是：

> **BusinessAgent 增加一个私有 `_execute_plan()` 方法。**

这样整个 Application 层仍然非常容易理解。

# 三、BusinessAgent 最小结构

M2 的 BusinessAgent 大致是：

```python
class BusinessAgent:

    def handle(
        self,
        user_request,
        runtime_context=None,
        existing_goal=None,
        existing_context=None,
    ):

        parse_result = self.goal_parser.parse(...)

        if parse_result.need_clarification:
            return ...

        goal = parse_result.goal

        plan = self.planner.plan(
            goal=goal,
            context=existing_context,
            capabilities=self.capability_catalog,
        )

        validate_plan(
            plan,
            self.capability_catalog,
        )

        return {
            "goal": goal,
            "plan": plan,
        }
```

M3 只是在后面多一段：

```python
context = ExecutionContext(
    goal=goal,
    current_plan=plan,
    known_context=existing_context or {},
)

return self._execute_plan(context)
```

也就是说：

```text
M2
Goal → Plan → return

M3
Goal → Plan → Execute → return
```

# 四、`_execute_plan()` 就是整个 T07 核心

我建议代码保持这种量级：

```python
def _execute_plan(
    self,
    context: ExecutionContext,
):

    replan_count = 0

    while True:

        step = get_next_ready_step(
            context.current_plan,
            context,
        )

        if step is None:
            return self._stopped_response(
                context,
                "no executable step",
            )

        result = execute_step(
            step=step,
            context=context,
            executor=self.capability_executor,
        )

        action = decide_continuation(
            plan=context.current_plan,
            context=context,
            last_result=result,
        )

        if action == ContinuationAction.CONTINUE:
            continue

        if action == ContinuationAction.FINISH:
            return self._success_response(
                context,
            )

        if action == ContinuationAction.ASK_USER:
            return self._clarification_response(
                context,
                result,
            )

        if action == ContinuationAction.STOP:
            return self._stopped_response(
                context,
                result,
            )

        if action == ContinuationAction.REPLAN:

            if replan_count >= 1:
                return self._stopped_response(
                    context,
                    "max replan reached",
                )

            old_plan = context.current_plan

            new_plan = self.planner.replan(
                context=context,
                last_result=result,
                capabilities=self.capability_catalog,
            )

            validate_plan(
                new_plan,
                self.capability_catalog,
            )

            validate_replan(
                old_plan=old_plan,
                new_plan=new_plan,
                context=context,
                capability_catalog=self.capability_catalog,
            )

            context.current_plan = new_plan
            replan_count += 1
```

对于 Demo，我觉得这已经足够。

甚至 `max_replans = 1` 都不用做配置项。

直接：

```python
if replan_count >= 1:
```

都可以。

等未来真的出现多轮 Replan 需求再抽。

# 五、这里有一个小细节：`get_next_ready_step() is None`

在正常执行路径里，这种情况理论上主要有两种：

### 正常完成

但是这种情况应该已经由上一轮：

```text
SUCCESS
→ decide_continuation()
→ FINISH
```

处理。

### Plan 不完整但没有 Ready Step

这就是异常状态：

```text
没有可执行 Step
但 Plan 也没正常完成
```

所以：

```python
if step is None:
    STOP
```

即可。

不要再做：

```text
DeadlockResolver
DependencyRecovery
```

Demo 不需要。

# 六、Response 也不要重新设计一大套

M2 已经有：

```text
PLAN_READY
CLARIFICATION_REQUIRED
FAILED
```

到了 M3，由于真正执行了，可以稍微调整。

我建议只需要：

```python
class BusinessAgentStatus(str, Enum):
    COMPLETED = "completed"
    CLARIFICATION_REQUIRED = "clarification_required"
    STOPPED = "stopped"
```

然后统一：

```python
@dataclass
class BusinessAgentResponse:
    status: BusinessAgentStatus
    goal: Goal
    plan: Plan
    context: dict
    message: str | None = None
```

但如果你当前项目不想再增加 DTO，甚至普通 dict 都可以：

```python
{
    "status": "completed",
    "goal": goal,
    "plan": context.current_plan,
    "context": context.known_context,
}
```

Demo 阶段我其实更倾向 **先继续使用普通 dict**。

不要为了 M3 再新建一整套 Response Contract。

# 八、T07 最重要的 Behaviour Case：正常路径

第一条先不要测试 Replan。

```text
Case A
正常执行完成
```

用户：

```text
帮我找当前值得关注的经营机会，
并围绕机会找到客户形成经营策略。
```

Fake Planner：

```text

S1 directional_insight
 ↓
S2 customer_targeting
 ↓
S3 strategy_generation
```

FakeCapability：

```text
S1 → SUCCESS
S2 → SUCCESS
S3 → SUCCESS
```


```text

```

这个 Case 证明：

> 不需要 Replan 时，系统不会乱 Replan。

# 十九、最终 M3-Lite Definition of Done

我建议正式把 Exit Criteria 定成这 6 条：

```text
① Plan 中 Capability 可以被真实执行。

② CapabilityResult 能回写 ExecutionContext。

③ SUCCESS 能自动推进后续 Step。

④ NO_RESULT 能触发一次 Replan，
   并生成新的 Plan V2。

⑤ 已成功 Step 不会因为 Replan 重复执行。

⑥ NEED_INFORMATION / BLOCKED / FAILED
   能产生不同的运行结果。
```

如果这六条全部通过：

> **M3 完成。**

不要因为：

```text
还没自动 Retry
还没自动恢复 Blocked
还不能连续 Replan 五次
还没有数据库
还没有并行执行
```

继续扩 M3。

这些都不是当前 Demo 需要证明的东西。
