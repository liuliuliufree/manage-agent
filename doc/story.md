# Demo 故事：一次有边界、可解释、可迭代的智能加保经营

## 故事要传达什么

这不是五个功能模块的串联演示，而是一个完整的经营闭环：

> 经营人员给出目标和边界，经营 Agent 在授权数据与合规规则范围内，自主发现机会、筛选客户、生成策略、编排执行，并根据客户反馈和受控实验持续优化经营。

---

## 第一幕：经营人员只提出目标｜能力项：① 定向洞察

周一上午，经营团队向经营中枢 Agent 下达任务：

> “分析近期值得重点经营的加保机会。在不增加客户打扰和合规风险的前提下，优先找到真正有需求、适合经营的客户。”

经营人员同时设定了三条边界：

- 只使用客户已授权、可用于经营的数据；
- 对营销许可、触达频次、产品适当性和人员资格进行强制校验；
- Agent 可以生成策略并编排任务，但具体产品推荐和销售沟通由具备资格的专业人员完成。

目标下达后，Agent 没有立即返回一份客户名单，而是先回答一个更重要的问题：

> 最近到底存在什么值得经营的机会？

---

## 第二幕：Agent 从多个候选机会中找到重点｜能力项：① 定向洞察

Agent 开始分析近期经营数据，并形成三个候选方向：

1. 家庭责任可能提升、现有重疾保障不足的客户；
2. 临近保单周年、适合进行保障回顾的客户；
3. 近期主动了解医疗保障、但尚未完成测算的客户。

对于每个方向，Agent 都展示客群规模、需求强度、预计响应、触达成本和合规限制，而不是只给出一个黑盒结论。

综合比较后，Agent 建议优先经营第一类机会：

> “家庭责任变化信号 + 重疾保障缺口”人群规模适中，近期主动保障行为更集中，预计有效响应较高，且可以先从保障检视切入，无需直接推荐产品。

这里所说的“家庭责任变化”并非 Agent 猜测客户隐私，而是来自客户主动更新、保障测算中填写且已授权用于服务经营的信息。页面同时显示数据来源、更新时间、授权状态和识别置信度。

至此，Agent 完成了机会发现，但还没有决定要联系谁。

---

## 第三幕：不是保障不足的人都应该被营销｜能力项：② 自动圈客

Agent 围绕这一机会继续筛选客户。

第一轮，它识别出存在一定保障缺口的客户；第二轮，它结合家庭责任、收入与持续缴费能力、已有保单结构、近期主动行为和产品适当性进行判断；第三轮，它排除不宜经营的客户，包括：

- 未授权接收相关营销信息的客户；
- 近期已被多次触达的客户；
- 已明确拒绝相关需求的客户；
- 正处于投诉、理赔等不适合营销阶段的客户；
- 当前不存在适合产品或无法通过初步适当性判断的客户。

最终，页面给出结果：

> 发现 86 名潜在机会客户；通过经营与合规初筛 41 名；其中 12 名为高优先级对象。

名单中的每位客户都有清晰的入选理由，而不是只有一个分数。

例如客户 C001：

> 35 岁；客户近期主动更新家庭信息；现有重疾保障与家庭责任测算相比存在明显缺口；近 30 天两次查看保障内容，并主动完成过一次初步测算；当前营销授权有效，近期触达频次较低。

Agent 给出的结论是：

> “客户存在较明确的保障检视需求，且目前处于适合开展服务型沟通的窗口。建议先帮助客户理解保障现状，不直接推荐具体产品。”

---

## 第四幕：为客户生成一条经营旅程｜能力项：③ 策略生成

Agent 没有简单输出“推荐重疾险”，而是为 C001 设计了一条递进式经营路径。

第一步，通过客户已授权且历史响应较好的渠道，发送一份家庭保障检视邀请，让客户先看到保障现状。

第二步，如果客户打开内容但未测算，则在频控范围内提供一次简短的测算入口，不连续打扰。

第三步，如果客户完成测算并主动查看相关保障内容，Agent 将其识别为意向增强，建议转交具备资格的专业人员进行一对一保障解读。

第四步，如果客户没有反馈，则等待一段时间，并根据客户的渠道偏好决定是否更换触达方式；如果客户明确拒绝，则立即结束本轮经营。

Agent 同时为不同响应准备分支，而不是生成一条所有客户都必须走完的固定流程。

页面上呈现完整的渠道编排：

> 口袋 E 保障报告 → 绿 E 通服务提醒 → 高意向后转专业人员 → 根据反馈继续、暂缓或退出

渠道选择依据也同步展示：客户授权、历史偏好、触达频控、响应表现和渠道成本。

---

## 第五幕：策略先过闸门，再进入执行｜能力项：④ 校验分发

策略生成后，Agent 不会直接把内容发送给客户，而是进入执行校验：

- 客户是否授权当前渠道和用途；
- 近期触达是否超过频控；
- 客户是否处于投诉、理赔等敏感阶段；
- 保障分析及候选产品是否满足适当性要求；
- 内容是否包含不合规表述；
- 承接人员是否具备对应服务和销售资格；
- 当前时间和渠道是否适合客户。

C001 的保障检视服务通过校验，任务进入执行队列；具体产品建议仍需由专业人员结合客户补充信息确认。

另一位高潜客户 C028 则被 Agent 拦截。虽然他也存在保障缺口，但最近三天已经收到多次经营触达。

Agent 没有为了追求转化继续营销，而是给出决定：

> “暂缓本轮经营，七天后重新评估；如客户主动发起咨询，可进入服务响应流程。”

这一刻，观看者可以清楚看到：经营 Agent 不只是帮助业务“多触达”，还负责在规则边界内决定何时不触达。

---

## 第六幕：客户行为改变，下一步动作随之改变｜能力项：⑤ 追踪迭代

C001 收到保障检视邀请后，首先打开了内容，随后完成保障测算，又主动浏览了相关保障页面。

Agent 没有因为一次点击就认定客户要购买，而是综合多项连续行为重新评分：

> 内容打开 + 完成测算 + 连续查看相关保障内容，使意向评分从 68 上升至 86。

页面同时展示评分变化的理由、信号时间和有效期限，避免一次历史行为永久影响客户判断。

Agent 随即调整经营动作：

> “客户主动兴趣明显增强，当前可能处于关键决策窗口。建议提升至最高跟进优先级，并在客户许可的服务时段内，由具备资格的专业人员进行保障解读。”

如果客户随后表示“暂时不考虑”，拒绝信号将优先于浏览行为，系统立即停止本轮营销，而不是继续追逐此前的高分。

---

## 第七幕：结果进入受控学习，而不是让模型自行改规则｜能力项：⑤ 追踪迭代

一段时间后，Agent 汇总这批客户的经营结果。

经营驾驶舱不只展示打开率和成交结果，还同时展示：

- 有效响应率和保障测算完成率；
- 专业人员接续率和有效线索率；
- 退订、拒绝和投诉情况；
- 单个有效机会的经营成本；
- 各渠道、时间段和策略分支的效果；
- 合规规则拦截数量及原因；
- 实验组相对于对照组的实际提升。

Agent 发现：对于“家庭责任提升型”客户，以保障缺口检视作为开场，比直接介绍产品获得了更高的测算完成率；先完成测算、再由专业人员承接的路径，有效线索率也更高。

但 Agent 不会直接修改生产策略。它形成一份优化建议：

> “建议提高保障检视路径的使用比例，并对触达时段进行下一轮小流量实验。”

经营人员查看依据和风险指标，审批通过后发布新的策略版本。系统保留版本、实验范围和回滚能力。

下一次遇到相似客户时，Agent 会优先采用已经验证有效的策略，由此形成可度量、可审核、可回退的持续优化闭环。

---

## Demo 最终形成的闭环

> 目标与边界设定 → 多机会洞察 → 可解释圈客 → 分层策略生成 → 全渠道编排 → 合规校验 → 人机协同执行 → 实时反馈 → 受控实验 → 策略迭代

它体现的不是“AI 自动发营销消息”，而是三个更重要的变化：

1. 从依赖人工寻找机会，变为 Agent 主动发现并量化机会；
2. 从名单式营销，变为基于客户状态、偏好和约束的动态经营；
3. 从一次性活动复盘，变为可解释、可验证、可持续优化的经营闭环。

---

## 面向领导的一句话介绍

> 过去是人找机会、人圈客户、人定策略、人追结果；现在，经营人员只需明确目标和边界，经营 Agent 就能在授权与合规范围内自主完成机会发现、客户筛选、策略生成和渠道编排，联动专业人员执行，并通过受控实验和客户反馈持续优化下一轮经营。
